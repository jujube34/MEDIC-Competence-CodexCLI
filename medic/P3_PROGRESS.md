## 材料解析与不可变快照

当前 `medic-extraction-v2` / `medic-runtime-p3-v10` 提供 PDF、DOCX、PPTX、XLSX 解析和私有材料库，使用独立受限进程提取，保留原文件、提取文本、检索文本、结构定位、质量状态及构建身份。PDF 已增加原页 PNG 预览及冻结文本块红框。实现及运行方式见 [ingestion/README.md](ingestion/README.md)。

- XLSX 未缓存公式行不再被空行逻辑跳过，公式、原始缓存、缓存状态和未重算标识分开保存。隐藏 sheet/行/列、稀疏宽表、合并范围与样式索引保留；不声称原始数值已按 Excel 显示格式渲染。
- DOCX 保留段落/表格结构及页眉页脚、脚注尾注、批注定位，不虚构页码。PPTX 按实际演示顺序保留 shape、table、notes 定位。修订、图片和未提取图形显式提示。
- PDF 使用原生文本块和坐标，不重复把整页文本算成另一份证据。扫描内容不生成占位证据；图片、矢量图、表单/批注、第二解析器不一致或失败均保留复核要求。尚未提供 OCR。
- 原文与规范化检索文本分开，引用 hash 绑定快照、locator 和 quote。重传生成新 snapshot，原始 blob 按内容复用，旧引用不会指向新文本。同源事件或相同原文件 hash 在汇总中合并，改事件标签不能制造额外独立佐证。
- `needs_review`、`empty`、`failed` 不能转换为自动评估 Material。源文件或快照被改写时拒绝读取，跨 tenant/employee 范围查询不返回材料。当前材料库是本地 SQLite/文件存储；应用 API 从服务端身份/授权映射取得范围，尚未接入生产 SSO。
- ZIP 总展开、成员数、单成员、文本块、字符数及输入大小有边界，XML 禁止 DTD/实体。真实子进程验证了超时和 Windows 内存限制。Windows 同时限制整个 Job 与单进程内存，允许 venv 启动器和解释器共两个进程；这不替代生产 OS/容器隔离。

## 应用接口与人工复核

实现见 [apps/api/README.md](apps/api/README.md)。API 只监听回环地址，使用服务器签发、仅存 hash 的短期 Bearer token；员工、岗位、租户和角色均从服务端目录取得。跨员工/跨租户不可读，管理员不自动拥有复核权；上级/总监必须具备该员工的明确复核授权，不能复核自己。每次访问检查失效与撤销，耗时解析后也重新检查授权。

评估创建将材料、标准、策略和范围冻结为输入；岗位推荐值独立保存，不注入 Agent 上下文。应用创建意图和 runtime 以稳定 creation key 连接，崩溃后重发请求恢复同一个 run 和预算。HTTP 请求只入队，可由持续服务自动领取。客户 49 岗位 / 833 推荐值候选可注册读取，保持 `awaiting_business_signoff`，不会被合成测试身份冒充正式发布。

人工建议、AI 建议和推荐值分别存储。复核保存要求精确引用或人工观察依据、改分理由、预期 revision；并发修订只放行一次，历史追加保留。补充材料限制同员工/周期，质量问题须逐项确认。定稿要求范围覆盖完整、风险核验完成，并记录限制处理；原 AI gate、报告和 runtime 状态不被改写。缺分与差距保留 null，合成定稿仍不是正式员工决定。

## 持续队列服务

`medic-runtime-p3-v5` 增加[本地持续调度入口](runtime/SERVICE.md)，发现 API 创建的任务后自动使用原 run 执行。当前限定 Windows，每个数据库一个调度服务、同时处理一个评估；评估内部继续遵守冻结并发预算。SQLite 使用 OS 文件锁，PostgreSQL 使用专用连接的 advisory lock。连接丢失不自动重新取得锁继续运行；Windows Job 关闭会终止所属解释器和后代进程。

调度 attempt 持久保存，自动重启最多三次；有效任务租约尚未到期时不抢占。恢复不改变旧预算、截止时间、已完成节点或原结果。失败、取消和已发布运行不会自动复活；旧构建与未知子进程失败留待运维检查，不自动转为演示报告。

完整回归 **209 项通过，其中 72 项使用真实 PostgreSQL、15 项为新增调度测试**，耗时 364.340 秒，见[调度回归摘要](evals/results/p3-service-contracts-verification.json)。首轮发现的 Windows 锁/Job 配置差异已修复；PostgreSQL 测试使用独立 schema，避免把共享测试库当作空队列。一次因测试数据库停止而中断的完整回归未计入通过。v5 冻结 86 个执行/资源文件，清单 hash 为 `e9024941566d5bbae6325f59f102723af53c0d7d0d018ab9800473602649b0bc`。

真实自动队列运行 `run-f7aabe00b502f884b00b717831eac17c` 已通过：先启动空队列服务，再通过 HTTP 上传虚构 DOCX 并创建评估；第二个调度实例被拒绝，原服务自动执行六个真实模型角色，只有一个服务 attempt。首评/二评均 B，Judge 与硬规则通过；**31 次请求、295,630 tokens，未结算请求为 0**。随后合成复核账号完成确认与定稿，原 AI 报告未改写。见[服务与 HTTP 验证](evals/results/p3-service-live-verification.json)及[模型、原文与版本绑定核验](evals/results/p3-service-runtime-verification.json)。本次不是页面报告 fixture，但输入和人工账号仍为合成测试，不代表专家质量评估或客户签收。测试数据库已停止；本地页面的 API 与空队列服务保留供继续使用。

### 真实调度进程强制终止与续接

合成 run `run-888bbc29cce743e8b91ed297f5c0db26` 在冻结 v5 上完成了实际故障注入：真实 Coordinator 已完成且下游请求进入预算后，用 Windows 句柄强制终止调度解释器。**16 个观察到的后代进程全部退出**，包含实际 Codex 进程；此检查发生在探针清理自己的外层 Job 之前。重启服务取得原数据库锁，将遗留服务 attempt 标记 interrupted，但未修改预算、已完成节点或有效任务租约。

## 数据库配置准入与 v6 发布

PostgreSQL 恢复测试发现，旧 `Store` 只按 URI 前缀判断后端，libpq 的 `user=... dbname=...` 连接串会被误当成本地文件路径。v6 增加无文件副作用的准入检查：接受 PostgreSQL URI 或明确的 SQLite 文件路径；拒绝关键字连接串、其它 scheme、空值、首尾空白和模糊的 Windows 驱动器相对路径。PostgreSQL 连接失败不触发 SQLite 降级，错误消息不包含输入凭据。
