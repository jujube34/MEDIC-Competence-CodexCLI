## 保留的流程结构

| 步骤 | 旧流程行为 | 迁移约束 |
| --- | --- | --- |
| 1 材料预处理与锚点扫描 | 本地处理材料块 | 使用冻结原文和可核验引用，不调用模型 |

## 必须显式迁移的差异

- `steps.py` 第 4 步 `targets` 和第 5 步 `qc_messages(..., targets=...)` 都传入推荐值。当前计划要求推荐值仅用于结果对照，评分和 QC 上下文均须排除。
- 第 2–5 步任一步异常会触发整轮 mock，汇总也可能使用 `MOCK.DEFAULT_LOCATOR`、预设理由与缺失项。正式对照必须保留失败和费用，不生成替代预测或引用。
- QC 的 `to=null` 在旧汇总条件中不会覆盖原档位。迁移应允许撤销不受支持的评分，并用契约测试验证空值一直保留到最终观测。
- 旧 `_apply_caps` 会事后改变档位。新适配器应记录原输出及规则结论，违规输出不能被悄悄修成合格结果；与 A/C 使用同一冻结 policy。
- 旧第 6 步有真实模型摘要调用，并在异常或超时后生成通用摘要。调用必须纳入预算，通用文本不得被当作该材料的模型判断。
- 旧标准来自静态客户常量；迁移使用实验绑定的标准、policy 和 parser 版本。不得复制旧岗位库替换当前 49 组合候选 Registry。

迁移后的 B 应单独命名和冻结实现、prompt 及差异清单，明确是“基于现有六步流程的约束迁移版”，不能写成“旧代码原样运行”。它需与 A/C 在相同输入、模型和预设预算条件下重新执行；历史 C 结果和当前 A 接入测试不能拼成完整随机对照。

## 执行前验收

适配器需验证完整业务输入与计划槽绑定、每步输出范围和引用、三批合并完整性、QC 弃权传播、独立会话、全部模型用量、持久预算和截止时间、失败不补分、终态重复收集不再次请求。已加入相应契约检查；工程测试及实际运行结果另行记录，不以本清单替代验收证据。专家标签及签收门槛仍需业务方提供。

迁移版使用完整冻结原文 span 索引替代旧正则锚点扫描，超过 200,000 UTF-8 字节的源输入执行前拒绝而不截断。QC 除 step3/step4 外可读取完整标准、材料元数据与冻结原文锚点；不接收 step2 或会话历史。保留六种可疑信号和三个风险扫描模式，但明确缺失痕迹本身不证明造假、低能力或合规。引用支持与归属判断仍需专家核验。失败不做模型修复重试，摘要失败没有通用业务文本兜底。当前限额为每槽 40 请求、并发 3、900 秒及设计指定的总 token 预算，单请求输出上限 16,384。

模型传输从旧 `LLMClient/call_json` 改为同一固定 Codex app-server、provider profile 和 namespace gateway，以便与 A/C 使用相同接入边界；每个模型步骤独立 thread/turn。提示词按上述步骤和当前严格契约重写，未复制客户私有 prompt 正文。这些变更都会影响结果，不能将迁移版的质量或费用归于旧原版。

B v2 将请求 schema 中的能力 code 限制为当前批次/范围的枚举，区分能力编号、criterion_id 和 employee_ref；来源事件和引用 ID/hash 也绑定当前输入。最终仍逐项验证完整性、去重、引用对应关系及 QC 处理，不以枚举约束替代业务验证。

B v3 进一步用固定位置约束提取/反向核查的能力覆盖，并增加确定性的可选引文目录：全量原文保留，长段按 200 字窗口、20 字重叠提供可复制的引用，短段不切分。schema 将引用 ID、原 span hash 与对应引文联合约束；不在输出后替换模型引用。此接口减少格式复制错误，但不能证明行为支持或个人归属，亦不能把它带来的可定位率直接归因于旧工作流。

B v4 将已有的“中/强证据必须有原文引用”规则同时表达在请求 schema 和提示词中。第三版真实输出曾在 15 项上违反该规则；原结果保持失败，不事后补引用。单请求网关上限从 150 秒改为 300 秒并绑定身份，总运行 900 秒、请求数、并发和总 token 预算不因此增加。该调整针对第三版真实超时，是否改善完整流程需新冻结实验验证。

B v5 将相同的完整输出 schema 同时放入提示正文与 `outputSchema` 参数，明确当前步骤不得沿用上一步字段。第四版两次反向核查都输出了额外提取/评分字段，原结果拒绝并保留；固定 Codex→网关的无模型传输探针确认 schema 未在该边界丢失。增加正文约束会增加输入 tokens，必须按新版本计费；不缩减原文、不替换结果字段，不把传输成功当作上游强约束证明。
