# 旧解析器迁移核查

2026-10-17 只读审查本地 `platform_v1_20261016/extract.py`，未修改客户原文件，未把旧模块接入 runtime。来源 hash 和合成复现摘要见 [legacy-parser-audit.json](../evals/results/legacy-parser-audit.json)。本记录属于 P3 准备，不代表 PDF/Office 解析已交付。

| 观察与代码位置 | 迁移要求 |
| --- | --- |
| `_parse_xlsx` 先按缓存值判断整行是否为空，再处理公式（约 600 行）。仅含未缓存公式的行被直接跳过。合成 A1=`=1+1`、无缓存的文件实际得到 0 个 sheet_row，且没有 `formula_uncached` 警告。 | 分别保留公式、缓存值和缓存状态；公式存在的行不是空行。未重算不能声称得到计算值。必须增加公式整行、部分缓存、隐藏 sheet 和宽表测试。 |
| XLSX 缓存值被转成行文本，公式只在缓存为空时用于占位（`_cell_text`、`_parse_xlsx`）。 | 每个单元格留精确坐标和类型；公式正文与缓存值单独保存，保留真实 sheet 名及稳定 ID。 |
| `clean_text` 折叠空白；表格空单元格以连字符占位。 | 原始提取文本、规范化检索文本分开；引用 hash 绑定固定提取快照，不能把拼接分隔符或占位符说成文件原文。 |
| `_parse_docx` 按正文结构生成段落/表格定位，未渲染页码；末尾记录脚注跳过。 | 保留结构定位；脚注、批注、修订及图片未解析时明确质量缺口，不虚构页码或完整覆盖率。 |
| `_parse_pdf` 同时保存文本块与整页文本，还对重复页眉折叠。扫描页仅生成未 OCR 提示。 | 页文本与块文本建立父子关系，不能作为独立重复证据；保留坐标和被折叠位置。扫描内容进入待 OCR/补材料状态，占位文字不能成为能力证据。 |
| `apply_file_budget` / `apply_run_budget` 删减块；另有宽行、长 slide/page 的限制。 | 解析存储完整快照；模型输入分页另受预算限制。确需截断时记录缺口范围并阻止把已读片段当成全部材料。 |
| Office ZIP 预检只统计 XML/rels/VML；`extract_file` 捕获异常后把异常文本附入警告。 | 增加总展开字节、成员数、输入大小、耗时/内存边界；错误仅输出固定代码，私有路径或文档内容不进入公开日志。 |

后续已按这些问题实现独立的解析与快照模块，见 [README.md](README.md) 和 [P3 进展](../P3_PROGRESS.md)。未缓存公式整行等合成缺陷已覆盖，未直接迁入旧解析器。解析失败、OCR 缺口和资源超限保留独立状态；它们不等于“材料没有体现能力”。应用授权与三端界面仍待实现。
